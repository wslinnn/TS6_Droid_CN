## 简介 / Overview

TS6 Mobile v2.10.0 以**语音链路重做**为主：采集不再依赖平台处理，回声消除改由内置 WebRTC AEC3 完成，并启用软件降噪；同时修复了安静频道里语音被攒批发送导致的「一段一段」。蓝牙耳机明确为仅输出设备，麦克风始终使用手机。另包含悬浮玻璃 bar 的实时背板模糊、服务器错误提示中文化，以及 tslib 0.2.0 适配。

本项目基于 [flamme-demon/TS6_Droid](https://github.com/flamme-demon/TS6_Droid)（原版）与 [YUAXI/TS6_Droid_CN](https://github.com/YUAXI/TS6_Droid_CN)（简中增强版）延续维护，遵循 GNU GPLv3 开源，感谢上游作者的贡献。

## 更新日志 (Changelog)

### 🎙 语音与音频
- **采集链路重做**：固定使用未处理的 `VOICE_PERFORMANCE` 采集，不再依赖平台侧 AEC/降噪/AGC；回声消除由内置 WebRTC AEC3 完成（48 kHz、10 ms 块处理），采集输出加固定 +6 dB 后置增益补偿裸麦响度
- **软件回声消除**：新增播放→采集参考流 FIFO（0 ms 对齐、空闲补零、有界漂移修正）；实测主路径回声明显削弱，复杂声学环境（大声外放、强混响）不保证
- **噪声抑制**：启用 WebRTC APM 内建 NS（HIGH 档）。风扇、空调这类持续噪声抑制明显；**键盘、鼠标按键这类短促声音只能部分压低，仍可能被对方听到**，这是当前方案的边界
- **发送节奏修复**：`sendAudio` 与事件循环共用同一条 native 线程，此前安静频道每 50 ms 才放行一批音频，接收端补帧造成断续；采集期间等待缩短到 5 ms，发送不再攒批
- 诊断与稳定性：新增 ERLE、播放缓冲峰值、入队→播放延迟、Opus 帧长分布；录音器停止/释放移入守护线程，避免原生停录挂死拖垮重建；数字静音不再触发重建

### 📱 蓝牙
- 蓝牙耳机固定作为 **A2DP 输出**，麦克风始终为手机麦克风。SCO 双向通路实现已移除——实测 SCO 状态、mode、`getRoutedDevice()` 均正常，但播放头恒为 0、录音全零，未产生可用音频通路，根因尚未定位。观测记录、已排除的假设与取证命令见仓库根 `BLUETOOTH-HEADSET-MIC.md`

### 🪟 界面
- 悬浮玻璃 bar 接入实时背板模糊与液态玻璃材质
- 修复文件操作后首刷自递归导致的崩溃

### 🛠 修复
- 服务器错误提示按 TeamSpeak 错误码本地化：限流、已在频道、频道/服务器密码、满员、权限不足、封禁等不再显示英文原文；未识别错误码保留原文便于排查
- 适配 tslib_multi v0.2.0：掉线事件模型更新，语音包补齐 FEC 解码与 PLC 入口

### 📦 工程
- 内置 `libtslib_jni.so` 更新至 tslib_multi `v0.1.4-han`（AEC3、APM 降噪、+6 dB 增益、FEC/PLC）
- 版本号 2.9.0-Han → 2.10.0-Han
